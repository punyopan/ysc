# BandGap-TH

[English](README.md) | **ภาษาไทย**

**เครือข่ายโทรศัพท์ไทยส่งผ่านเสียงในย่าน 300–3400 Hz ขณะที่ระบบตรวจจับเสียงปลอมถูกฝึกด้วยเสียง 16 kHz โครงงานนี้วัดว่าการตรวจจับยังทำงานได้หรือไม่หลังจากเครือข่ายตัดข้อมูลส่วนใหญ่ของสัญญาณทิ้งไป และหาความถี่ตัดที่การตรวจจับหยุดทำงาน**

มิจฉาชีพที่ใช้เสียงโคลนในประเทศไทยเข้าถึงเหยื่อผ่านทางโทรศัพท์ แต่ระบบตรวจจับที่สร้างขึ้นเพื่อรับมือกลับถูกฝึกและประเมินด้วยเสียง wideband แบบสะอาดซึ่งไม่มีสายโทรศัพท์ใดส่งผ่าน BandGap-TH วัดว่าช่องว่างดังกล่าวใหญ่เพียงใด แยกสาเหตุของช่องว่างนั้น และทดสอบว่าสามารถฝึกโมเดลให้ชดเชยได้หรือไม่

งานวิจัยนี้ออกแบบมาเพื่อตอบคำถามหนึ่งข้อด้วยตัวเลข:

> การตรวจจับข้ามเกณฑ์ล้มเหลวเมื่อความถี่ต่ำกว่า **X** kHz ขณะที่ช่องสัญญาณโทรศัพท์ไทยแบบทั่วไปส่งผ่านได้ถึง 3.4 kHz ดังนั้นระบบตรวจจับประเภทนี้ **ใช้ได้ / ใช้ไม่ได้** กับเสียงโทรศัพท์ภายใต้เงื่อนไขที่ทดสอบ

`X` คือสิ่งที่การทดลองนี้วัด ส่วนอื่นทั้งหมดใน repository นี้ ไม่ว่าจะเป็นการแยกสาเหตุ กราฟความถี่ตัด ค่าการกู้คืน หรือช่วงความเชื่อมั่นจาก bootstrap ล้วนเป็นหลักฐานที่รองรับประโยคดังกล่าว

BandGap-TH เป็นข้อเสนอโครงงานวิจัยสำหรับ YSC Thailand

## ปัญหา

ช่องสัญญาณโทรศัพท์ G.711 แบบทั่วไปส่งผ่านเสียงในย่านแคบประมาณ 300–3400 Hz [3] ร่องรอยบางส่วนที่ใช้แยกเสียงสังเคราะห์อาจอยู่นอกย่านดังกล่าว ดังนั้นระบบตรวจจับที่ฝึกด้วยเสียง wideband แบบสะอาดอาจพึ่งพาข้อมูลที่ไม่มีอยู่ในเสียงโทรศัพท์

งานวิจัยที่ตีพิมพ์แล้วแสดงว่าโคเดกอาจทำให้ประสิทธิภาพการตรวจจับลดลง [2, 10] และมีงานประเมินเสียงโทรศัพท์ภาษาไทยอยู่แล้ว [4, 12] อย่างไรก็ตาม งานเหล่านี้ยังไม่ได้แยกผลสองส่วนที่เกิดขึ้นพร้อมกันในช่องสัญญาณ G.711 อย่างชัดเจน:

| | ทำอะไร | ผลที่ตามมา |
| --- | --- | --- |
| **การลดแบนด์วิดท์** | ตัดความถี่ที่สูงกว่าประมาณ 3.4 kHz | ข้อมูลในย่านที่ถูกตัดจะไม่เหลือให้ระบบตรวจจับใช้ |
| **Companding** | แปลงเสียง linear 16-bit เป็น logarithmic 8-bit แบบ A-law หรือ μ-law | ข้อมูลยังคงอยู่ แต่สัญญาณเปลี่ยนไปจากการ quantize |

งานวิจัยส่วนใหญ่มักใช้โคเดกครบทั้งกระบวนการแล้วรายงานผลรวมเพียงค่าเดียว การวัดผลทั้งสองส่วนแยกกันจะแสดงให้เห็นว่าการฝึกโมเดลมีแนวโน้มช่วยได้หรือไม่ หรือข้อจำกัดที่ใหญ่กว่าคือแบนด์วิดท์ที่หายไป

## คำถามวิจัย

1. **การแยกสาเหตุ:** จาก EER ที่เพิ่มขึ้นเมื่อใช้ G.711 จำลองกับเสียงภาษาไทย มีส่วนที่สัมพันธ์กับการลดแบนด์วิดท์เท่าใด และสัมพันธ์กับ companding เท่าใด
2. **ความสัมพันธ์ระหว่างระดับกับผล:** ประสิทธิภาพการตรวจจับเปลี่ยนไปอย่างไรเมื่อค่อย ๆ ลดความถี่ตัดของ low-pass filter และที่ความถี่ใดประสิทธิภาพจึงข้ามเกณฑ์ล้มเหลวที่ลงทะเบียนไว้ล่วงหน้า
3. **การบรรเทาผลกระทบ:** การฝึกด้วยเสียงที่ถูกจำกัดแบนด์วิดท์ช่วยกู้ประสิทธิภาพที่สูญเสียไปบางส่วนได้หรือไม่ และได้มากเพียงใด

## สมมติฐาน

- **H1 — การแยกสาเหตุ:** การลดแบนด์วิดท์ส่งผลมากกว่า companding
- **H2 — ปริมาณ–ผล:** EER เพิ่มขึ้นทางเดียวเมื่อความถี่ตัดลดลง และมีเกณฑ์การพังที่ระบุได้
- **H3 — การบรรเทา:** การเพิ่มข้อมูลแบบจำกัดแบนด์วิดท์ช่วยลด `ΔEER` เมื่อเทียบกับ baseline ที่ใช้สถาปัตยกรรมเดียวกันและฝึกด้วยเสียงสะอาด

การออกแบบนี้สมมาตร กล่าวคือไม่ได้สร้างขึ้นเพื่อยืนยัน H1 สมมติฐานทุกข้อมีผลลัพธ์ที่รายงานได้ไม่ว่าผลจะออกมาในทิศทางใด และเกณฑ์ทั้งหมดถูกกำหนดไว้ก่อนการให้คะแนน จึงไม่สามารถเลื่อนเป้าหมายหลังเห็นผลได้ หาก companding ส่งผลมากกว่าที่คาด การฝึกแบบ channel-aware อาจมีโอกาสช่วยได้มากขึ้น หากการเพิ่มข้อมูลช่วยได้น้อยหรือไม่ช่วยเลย ผลดังกล่าวจะสอดคล้องกับการสูญเสียข้อมูลจากการลดแบนด์วิดท์ แม้ว่ายังต้องพิจารณาคำอธิบายอื่นด้วย

## การออกแบบ

![รูปแบบการทดลอง BandGap-TH](docs/architecture.svg)

ไฟล์ต้นฉบับที่แก้ไขได้: [`docs/architecture.mmd`](docs/architecture.mmd)

**ชุดแยกสาเหตุ:** เสียงต้นทางแต่ละไฟล์ในชุดทดสอบจะสร้างเงื่อนไขที่จับคู่กันสี่แบบ:

| ID | เงื่อนไข | ประกอบด้วย |
| --- | --- | --- |
| C0 | linear PCM 16 kHz แบบสะอาด | ค่าอ้างอิง |
| C1 | **linear PCM** 8 kHz แบบไป–กลับ | แบนด์วิดท์เท่านั้น |
| C2 | G.711 μ-law | แบนด์วิดท์ + companding |
| C3 | G.711 A-law | แบนด์วิดท์ + companding |

**C1 คือส่วนที่เป็นการมีส่วนร่วมเชิงระเบียบวิธีของโครงงานนี้** งานที่ตีพิมพ์ก่อนหน้ามักใช้โคเดกครบทั้งกระบวนการแล้วรายงานค่าการเสื่อมรวมเพียงค่าเดียว C1 ตัดย่านความถี่สูงออกแต่ยังคงความละเอียดแบบ linear 16-bit จึงเกิดการลดแบนด์วิดท์โดยไม่มี companding การเปรียบเทียบ C1 กับ C0 แยกผลของแบนด์วิดท์ออกมา ส่วนการเปรียบเทียบ C1 กับ C2 และ C3 ใช้ประมาณการเปลี่ยนแปลงเพิ่มเติมที่สัมพันธ์กับ companding หลังจากลดแบนด์วิดท์แล้ว หากไม่มีเงื่อนไขควบคุมนี้จะไม่สามารถแยกสาเหตุทั้งสองออกจากกันได้

**ชุดกวาดความถี่:** เริ่มจากค่าอ้างอิง 16 kHz ที่ไม่ใช้ฟิลเตอร์ แล้วตามด้วยความถี่ตัดของ low-pass filter ที่ 6 kHz, 4 kHz, 3.4 kHz, 2.5 kHz, 1.5 kHz และ 800 Hz

ชุดกวาดความถี่คงอัตราการสุ่มตัวอย่างไว้ที่ 16 kHz และเปลี่ยนเฉพาะความถี่ตัดของฟิลเตอร์ วิธีนี้ป้องกันไม่ให้การ resample กลายเป็นตัวแปรเพิ่ม ชุดแยกสาเหตุยังต้องแปลงแบบไป–กลับผ่าน 8 kHz เพื่อแทน G.711 แต่ชุดกวาดความถี่ไม่ต้องทำเช่นนั้น

## ผลลัพธ์หลัก

```text
ส่วนของแบนด์วิดท์  = EER_C1 − EER_C0
ส่วนของ companding = mean(EER_C2, EER_C3) − EER_C1
ช่องว่างการแยกสาเหตุ = ส่วนของแบนด์วิดท์ − ส่วนของ companding

Recovery = (ΔEER_baseline − ΔEER_augmented) / ΔEER_baseline
```

การเปรียบเทียบแต่ละรายการใช้ paired cluster bootstrap ตามไฟล์เสียงต้นทาง โดยเงื่อนไขทั้งหมดที่สร้างจากไฟล์เดียวกันจะถูกสุ่มไปพร้อมกันในแต่ละตัวอย่าง bootstrap

กราฟความถี่ตัดจะรวมเกณฑ์ล้มเหลวที่ลงทะเบียนไว้ล่วงหน้าสองแบบ ได้แก่ ความถี่ตัดที่ EER เพิ่มเป็นสองเท่า และความถี่ตัดที่ EER ถึง 10%

## ทำไมคำตอบจึงสำคัญ

วิธีแก้ปัญหาการเสื่อมจากช่องสัญญาณที่ใช้กันทั่วไปคือ channel-aware augmentation กล่าวคือฝึกระบบตรวจจับด้วยเสียงที่ถูกทำให้เสื่อมเพื่อให้ระบบเรียนรู้ที่จะรับมือ วิธีนี้มีโอกาสได้ผลเฉพาะเมื่อความเสียหายมาจาก companding เพราะ companding เปลี่ยนแปลงข้อมูลที่ยังคงอยู่ในสัญญาณ แต่หากความเสียหายส่วนใหญ่มาจากการลดแบนด์วิดท์ ข้อมูลนั้นถูกตัดออกไปแล้วและการฝึกไม่สามารถกู้กลับคืนมาได้

| หากความเสียหายส่วนใหญ่มาจาก… | จุดที่การแก้ไขต้องเกิดขึ้น |
| --- | --- |
| **Companding** | ที่ตัวโมเดล การฝึกแบบ channel-aware และ representation ที่ทนทานกว่ายังมีโอกาสช่วยได้ |
| **แบนด์วิดท์** | ที่ช่องทางส่งผ่าน ต้องใช้เส้นทาง wideband เช่น VoLTE หรือ VoIP ที่ใช้ Opus เพราะย่านความถี่ที่ถูกตัดออกไปแล้วไม่สามารถฝึกให้กลับคืนมาได้ |

ความแตกต่างนี้เกี่ยวข้องโดยตรงกับการตัดสินใจว่าความพยายามด้านการป้องกันการฉ้อโกงควรลงทุนกับระบบตรวจจับที่ดีขึ้นหรือกับเส้นทางการโทรแบบ wideband และเรายังไม่พบงานตีพิมพ์ที่รายงานการแยกผลดังกล่าวโดยตรง กราฟความถี่ตัดจะผูกคำถามนี้เข้ากับค่าความถี่ที่วัดได้

## การสาธิต

การกวาดความถี่ตัดทำหน้าที่เป็นการสาธิตด้วย และเป็นส่วนหนึ่งของงานที่ผูกมัดไว้ ไม่ใช่ส่วนขยายที่เลือกทำ เสียงพูดภาษาไทยหนึ่งประโยคจะถูกเล่นที่ทุกความถี่ตัดในชุดกวาด ได้แก่ ค่าอ้างอิง 16 kHz แล้วตามด้วย 6 kHz, 4 kHz, 3.4 kHz, 2.5 kHz, 1.5 kHz และ 800 Hz ขณะเดียวกันจะแสดงคะแนนของระบบตรวจจับเทียบกับกราฟที่วัดได้ โดยทำเครื่องหมายขอบย่านโทรศัพท์ที่ 3.4 kHz และเกณฑ์การพังบนแกนความถี่ การสาธิตนี้ทำงานบนแล็ปท็อปจากไฟล์ผลทำนาย Tier 1 โดยไม่ต้องใช้ GPU ไม่ต้องมี toolchain สำหรับ deployment และไม่ต้องพึ่ง tier เสริม

กฎการนำเสนออยู่ใน [`docs/feasibility.md`](docs/feasibility.md): ต้องแสดงคะแนนและเกณฑ์การตัดสินที่ตรึงไว้พร้อมอัตราความผิดพลาดที่วัดได้ ห้ามแสดงเพียงคำตัดสินว่าเสียงจริงหรือปลอม และต้องใช้เฉพาะเสียงที่โครงงานเป็นเจ้าของหรือเสียงจากชุดข้อมูลที่ใบอนุญาตอนุญาตให้ใช้

## ขอบเขตที่กำหนดไว้ล่วงหน้า

ขอบเขตเหล่านี้ถูกกำหนดไว้ล่วงหน้าและตรึงไว้กับโพรโทคอล เพื่อไม่ให้ข้อกล่าวอ้างขยายออกไปหลังจากเห็นผลแล้ว

- ไม่กล่าวอ้างว่าศึกษา **โทรศัพท์จริง** สายจริงยังมี packet loss, jitter, การแปลงโคเดก คุณลักษณะของเครื่องโทรศัพท์ เสียงสะท้อนในห้อง และการควบคุมเกน ซึ่งไม่ได้ศึกษาในโครงงานนี้ งานนี้ใช้ G.711 จำลองแบบออฟไลน์
- ไม่กล่าวอ้างว่าเป็นงานประเมินโทรศัพท์ภาษาไทยงานแรก ซึ่งเป็นของ [4, 12]
- ไม่กล่าวอ้างข้อโต้แย้งเรื่อง threshold transfer ซึ่งเป็นของ [19]
- ไม่กล่าวอ้างว่าเสนอสถาปัตยกรรมใหม่หรือสร้างสถิติสูงสุดใหม่
- ไม่กล่าวอ้างว่าทนต่อโมเดลสร้างเสียงที่ไม่เคยพบมาก่อน
- ไม่กล่าวอ้างความแน่นอนทางนิติวิทยาศาสตร์จากคะแนนของระบบตรวจจับ
- ไม่อนุมานว่าผลลัพธ์ใช้ได้กับผู้พูดภาษาไทยทุกคนหรือ deepfake ทั้งหมดในอนาคต

## สถานะ

อยู่ในขั้นข้อเสนอโครงงานวิจัยและการออกแบบการทดลอง ยังไม่มีโค้ดฝึก ชุดข้อมูล ผลการทำนาย หรือ checkpoint ใน repository นี้

## ใบอนุญาต

ข้อความต้นฉบับและโค้ดในอนาคตใช้ใบอนุญาต MIT ส่วนชุดข้อมูล โมเดล มาตรฐาน และซอฟต์แวร์ภายนอกยังคงอยู่ภายใต้ใบอนุญาตและข้อจำกัดการเข้าถึงของเจ้าของแต่ละราย
