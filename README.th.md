# ScaleGap-TH

[English](README.md) | **ภาษาไทย**

**เส้นความสัมพันธ์ระหว่างความแม่นยำกับขนาดโมเดลของระบบตรวจจับเสียงปลอมภาษาไทย จะชันขึ้นหรือไม่เมื่อเสียงผ่านช่องสัญญาณโทรศัพท์**

ScaleGap-TH เป็นข้อเสนอโครงงานสำหรับ YSC Thailand ที่วัดว่า "ต้นทุนความแม่นยำ" ของการลดขนาดระบบตรวจจับเสียงปลอมภาษาไทยเปลี่ยนไปอย่างไร เมื่อเสียงเข้ามาทางช่องสัญญาณโทรศัพท์ G.711 แทนไมโครโฟนที่สะอาด และวัดว่าโมเดลที่เล็กพอจะทำงานบนโทรศัพท์หรือบอร์ดคอมพิวเตอร์ขนาดเล็กยังใช้งานได้จริงหรือไม่ภายใต้ช่องสัญญาณนั้น

## คำถามวิจัย

> การเข้ารหัสโทรศัพท์ G.711 ทำให้ระบบตรวจจับเสียงปลอมภาษาไทยที่มีขนาดเล็ก แย่ลงมากกว่าระบบขนาดใหญ่หรือไม่

มิจฉาชีพที่ใช้เสียงปลอมในไทยติดต่อเหยื่อผ่านโทรศัพท์ และเส้นทางโทรศัพท์เป็นแบบ narrowband: G.711 ตัดความถี่เหนือประมาณ 3.4 kHz ทิ้ง ขณะที่ร่องรอย (artifact) ของ vocoder และ TTS ส่วนใหญ่อยู่เหนือย่านความถี่นั้น โมเดลขนาดใหญ่อาจยังมีสัญญาณสำรองให้ใช้ในย่านที่เหลือ แต่โมเดลขนาดเล็กอาจใช้ความจุที่มีอยู่ทั้งหมดไปกับย่านความถี่ที่เพิ่งถูกตัดทิ้ง หากเป็นเช่นนั้น คำแนะนำทั่วไปที่ว่า "ใช้โมเดลเล็กสำหรับงาน edge" จะใช้ไม่ได้ในจุดที่ต้องใช้จริง

### เหตุใดคำถามนี้จึงยังไม่มีคำตอบ

งานก่อนหน้าตอบคำถามนี้แยกเป็นส่วน ๆ แต่ไม่เคยตอบส่วนที่เป็นปฏิสัมพันธ์ระหว่างกัน:

- **ช่องว่างระหว่าง benchmark กับข้อมูลจริง** — Müller และคณะรายงานว่า RawNet2 มี EER เพิ่มจาก 3.154% บน ASVspoof 2019 LA เป็น 37.819% บนชุด In-the-Wild [1] ซึ่งวัด domain shift ไม่ใช่ขนาดโมเดล
- **ความทนทานต่อโคเดก** — ชุดทดสอบ ADD-C ประเมินโคเดก 6 ตัว คือ AMR-WB, EVS, IVAS, Opus, Speex (WB) และ SILK [2] ทั้งหมดเป็น wideband และ **ไม่มี G.711** ซึ่งเป็น narrowband
- **เงื่อนไขโทรศัพท์จริง** — ASVspoof 2021 LA มีการส่งผ่านโทรศัพท์จริงรวมถึง a-law และ μ-law [10] แต่เป็นภาษาอังกฤษ ไม่มีแกนขนาดโมเดล และไม่มีตัวควบคุมที่แยกผลของการจำกัดแบนด์วิดท์ออกจาก companding
- **โมเดลขนาดเล็ก** — AASIST-L ให้ความแม่นยำที่แข่งขันได้ด้วยพารามิเตอร์ราว 85K [7] และมีงานต่อมาที่ลดขนาด backend ของ AASIST เพื่อการใช้งานจริง [11] แต่ทั้งหมดรายงานประสิทธิภาพบนเงื่อนไขเสียงสะอาด ไม่ใช่ภายใต้ช่องสัญญาณ

ยังไม่มีงานตีพิมพ์ใดรายงานการเสื่อมของ EER ในฐานะฟังก์ชันของขนาดโมเดลภายใต้การเข้ารหัสโทรศัพท์แบบ narrowband และไม่มีงานใดแยกผลของแบนด์วิดท์ออกจาก companding ควบคู่กันไป

## สมมติฐาน

- **H1 — เส้นชันขึ้น (หลัก):** G.711 ทำให้ EER เพิ่มขึ้นมากกว่าในโมเดลขนาดเล็กเมื่อเทียบกับโมเดลขนาดใหญ่
- **H2 — การเสื่อมโดยรวม:** G.711 ทำให้ EER เพิ่มขึ้นเมื่อเทียบกับเสียงสะอาดที่จับคู่กัน ในระบบตรวจจับส่วนใหญ่
- **H3 — สัดส่วนจากแบนด์วิดท์:** ส่วนหนึ่งของการเสื่อมอธิบายได้ด้วยการลดแบนด์วิดท์เหลือ 8 kHz เพียงอย่างเดียว ส่วนที่เหลืออาจมาจาก companding แบบ A-law/μ-law
- **H4 — ความเป็นไปได้ในการใช้งานจริง:** มีระบบตรวจจับอย่างน้อยหนึ่งระบบที่ต่ำกว่า 100K พารามิเตอร์ ซึ่งยังใช้งานได้ภายใต้ G.711 พร้อมผ่านเกณฑ์ real-time factor และหน่วยความจำที่กำหนดไว้ล่วงหน้าบนอุปกรณ์เป้าหมาย

H1 พิสูจน์ผิดได้และมีประโยชน์ไม่ว่าผลจะออกทางใด หากสนับสนุน แปลว่าห้ามนำโมเดลเล็กไปใช้กับเสียงโทรศัพท์อย่างไม่ระวัง หากถูกปฏิเสธ แปลว่าโมเดลราคาถูกปลอดภัยสำหรับช่องสัญญาณนี้ ซึ่งน่าประหลาดใจกว่าและนำไปใช้ได้จริงพอ ๆ กัน

## รูปแบบการทดลอง

![รูปแบบการทดลอง ScaleGap-TH](docs/architecture.svg)

ไฟล์ต้นฉบับที่แก้ไขได้: [`docs/architecture.mmd`](docs/architecture.mmd)

เสียงทดสอบแต่ละไฟล์จะมีเวอร์ชันที่จับคู่กัน 4 เงื่อนไข:

1. **C0 — Clean:** PCM ต้นฉบับที่ 16 kHz
2. **C1 — Bandwidth control:** แปลงเป็น linear PCM 8 kHz แล้วแปลงกลับเป็นอัตราสุ่มของโมเดล
3. **C2 — G.711 μ-law:** เข้ารหัสและถอดรหัสที่ 8 kHz
4. **C3 — G.711 A-law:** เข้ารหัสและถอดรหัสที่ 8 kHz

C1 ใช้แยกผลจากการจำกัดแบนด์วิดท์โทรศัพท์ออกจากผลของ G.711 companding ทุก transformation จะถูกใช้กับทั้งเสียงจริงและเสียงปลอมในลักษณะเดียวกัน และใช้ resampler ชุดเดียวที่ตรึงเวอร์ชันไว้ทุกเงื่อนไข

## ระบบตรวจจับ — แกนขนาดโมเดล

ขนาดโมเดลคือตัวแปรที่จัดกระทำ จึงเลือกใช้เฉพาะระบบที่ตีพิมพ์แล้ว ครอบคลุมราว 3 อันดับขนาด:

| ระบบ | ขนาดโดยประมาณ | บทบาท |
| --- | --- | --- |
| LFCC-GMM | ไม่ใช้โครงข่ายประสาท | เส้นฐานแบบดั้งเดิม |
| AASIST-L | ~85K พารามิเตอร์ | ตัวเลือกสำหรับใช้บนอุปกรณ์ |
| AASIST | ~297K พารามิเตอร์ | โมเดลเล็กสำหรับอ้างอิง |
| Frozen WavLM + linear head | ~94M (ตรึงน้ำหนัก) | ตัวแทนเสียงขนาดใหญ่แบบคงที่ |
| WavLM + LoRA adapter หนึ่งชุด | ~94M + adapter | ตัวแทนเสียงขนาดใหญ่แบบปรับได้ |

ตัวเลขพารามิเตอร์ข้างต้นเป็นค่าโดยประมาณ ค่าจริง จำนวน MACs และเวลาประมวลผลบนอุปกรณ์จะ **วัดจากคอนฟิกที่ตรึงแล้วและรายงาน** ไม่ใช่คัดลอกจากบทความ

**โครงงานนี้ไม่เสนอ architecture ใหม่** การออกแบบโครงข่ายขนาดจิ๋วอยู่นอกขอบเขตอย่างชัดเจน เพราะ AASIST-L ครองช่วงขนาดนั้นอยู่แล้ว และสิ่งที่โครงงานนี้เสนอคือ "เส้น" ไม่ใช่ "โมเดล"

## ผลลัพธ์หลัก

สำหรับแต่ละระบบ โดยให้ `EER_G711 = mean(EER_C2, EER_C3)`:

```text
ΔEER_G711(m) = EER_G711(m) − EER_C0(m)
```

H1 ทดสอบด้วยวิธี **difference-in-differences** ระหว่างระบบสองตัวบนไฟล์เสียงชุดเดียวกันที่จับคู่กัน:

```text
DiD(small, large) = ΔEER_G711(small) − ΔEER_G711(large)
```

การเปรียบเทียบนี้มีกำลังทางสถิติเพียงพอ เพราะหน่วยของ bootstrap คือไฟล์เสียงต้นทาง ไม่ใช่จำนวนระบบตรวจจับ โดยกำหนดไว้ล่วงหน้าสองคู่:

- **คู่ช่วงกว้าง (หลัก):** AASIST-L เทียบกับ WavLM+LoRA ครอบคลุมช่วงขนาดกว้างที่สุด แต่ขนาดพันกับตระกูล architecture
- **คู่ภายในตระกูลเดียวกัน (รอง):** AASIST-L เทียบกับ AASIST ควบคุม architecture ไว้ แต่ช่วงขนาดแคบกว่า

เส้น frontier ของทั้ง 5 ระบบจะรายงานเชิงพรรณนาเป็น Pareto curve ไม่ใช่การถดถอยบนขนาดโมเดล เพราะด้วยระบบเพียง 5 ตัว การประมาณความชันมีกำลังทางสถิติต่ำ และจะรายงานพร้อมความไม่แน่นอนเสมอ

รายงานเพิ่มเติม:

- ช่วงความเชื่อมั่น 95% จาก paired cluster bootstrap ตามไฟล์เสียงต้นทาง
- ผลเมื่อใช้ threshold จาก clean development set โดยไม่ปรับ threshold บน test set
- การแยกผลระหว่างแบนด์วิดท์กับ companding จากเงื่อนไข C1
- ค่าที่วัดได้จริงของพารามิเตอร์ MACs real-time factor หน่วยความจำสูงสุด และขนาดไฟล์โมเดลบนอุปกรณ์เป้าหมาย

## ส่วนการใช้งานจริง

ระบบที่เล็กที่สุดซึ่งผ่านเกณฑ์ความแม่นยำจะถูก export ไปรันบนอุปกรณ์เป้าหมายที่ประกาศไว้ ด้วยอินพุตที่ผ่าน G.711 พร้อมรายงาน real-time factor และหน่วยความจำสูงสุดภายใต้ภาระต่อเนื่อง ส่วนนี้เป็น "การวัด" ไม่ใช่ "ผลิตภัณฑ์" โดยตอบว่าปลายด้านเล็กของเส้น frontier เอื้อมถึงได้จริงหรือไม่บนฮาร์ดแวร์ราคาที่ไทยจ่ายไหว

## สิ่งที่โครงงานนี้จะไม่กล่าวอ้าง

- ไม่กล่าวอ้างว่าเสนอ architecture ใหม่ หรือทำสถิติสูงสุดใหม่บน benchmark ใด
- ไม่กล่าวอ้างว่าขนาดโมเดลเพียงอย่างเดียวอธิบายเส้น frontier ได้ เพราะตระกูล architecture พันอยู่กับขนาด จึงต้องรายงานคู่ภายในตระกูลเดียวกันควบคู่ไปด้วย
- ไม่กล่าวอ้างว่าสามารถรองรับโมเดลสร้างเสียงที่ไม่เคยพบ
- ไม่กล่าวว่าการจำลอง G.711 เหมือนเครือข่ายโทรศัพท์ไทยจริงทุกประการ
- ไม่ทดสอบ LINE, Discord, WhatsApp, replay, packet loss หรือเสียงรบกวน
- ไม่ใช้คะแนนจากโมเดลเพียงค่าเดียวเป็นหลักฐานยืนยันว่าเสียงจริงหรือปลอม
- ไม่สรุปว่าผลใช้ได้กับผู้พูดภาษาไทยทุกคนหรือ deepfake ในอนาคตทั้งหมด
