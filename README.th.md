# BandGap-TH

[English](README.md) | **ภาษาไทย**

**ช่องสัญญาณโทรศัพท์ไทยส่งผ่านเสียงในย่าน 300–3400 Hz ส่วนระบบตรวจจับเสียงปลอมถูกฝึกด้วยเสียง 16 kHz โครงงานนี้วัดว่าการตรวจจับยังทำงานได้หรือไม่หลังจากช่องสัญญาณตัดข้อมูลส่วนใหญ่ทิ้งไป และหาความถี่ที่การตรวจจับหยุดทำงาน**

มิจฉาชีพที่ใช้เสียงปลอมในไทยติดต่อเหยื่อทางโทรศัพท์ แต่ระบบตรวจจับที่สร้างขึ้นมารับมือกลับถูกฝึกและวัดผลด้วยเสียง wideband แบบสะอาดซึ่งไม่มีในสายโทรศัพท์จริง BandGap-TH วัดว่าช่องว่างนี้ใหญ่เพียงใด แยกว่าอะไรเป็นสาเหตุ และทดสอบว่าฝึกโมเดลให้ชดเชยได้หรือไม่

โครงงานนี้ออกแบบมาเพื่อตอบคำถามเดียวด้วยตัวเลข:

> การตรวจจับข้ามเกณฑ์ล้มเหลวที่ความถี่ต่ำกว่า **X** kHz ขณะที่ช่องสัญญาณโทรศัพท์ไทยแบบทั่วไปส่งผ่านได้ 3.4 kHz ดังนั้นระบบตรวจจับกลุ่มนี้ **ใช้ได้ / ใช้ไม่ได้** กับเสียงโทรศัพท์ภายใต้เงื่อนไขที่ทดสอบ

`X` คือสิ่งที่การทดลองนี้วัด ส่วนอื่นทั้งหมดใน repository นี้ ทั้งการแยกสาเหตุ กราฟความถี่ตัด ค่าการกู้คืน และช่วงความเชื่อมั่นจาก bootstrap คือหลักฐานที่รองรับประโยคดังกล่าว

BandGap-TH เป็นข้อเสนอโครงงานสำหรับ YSC Thailand

## ปัญหา

ช่องสัญญาณ G.711 แบบทั่วไปส่งผ่านเสียงในย่านแคบประมาณ 300–3400 Hz [3] ร่องรอยบางส่วนที่ใช้แยกเสียงสังเคราะห์อาจอยู่นอกย่านนี้ ดังนั้นโมเดลที่ฝึกด้วยเสียง wideband แบบสะอาดอาจพึ่งพาข้อมูลที่ไม่มีอยู่ในเสียงโทรศัพท์

งานวิจัยก่อนหน้าแสดงว่าโคเดกอาจทำให้การตรวจจับแย่ลง [2, 10] และมีงานประเมินเสียงโทรศัพท์ภาษาไทยแล้ว [4, 12] อย่างไรก็ตาม งานเหล่านี้ยังไม่ได้แยกผลสองส่วนที่เกิดขึ้นพร้อมกันในช่องสัญญาณ G.711 อย่างชัดเจน:

| | ทำอะไร | ผลที่ตามมา |
| --- | --- | --- |
| **การลดแบนด์วิดท์** | ตัดความถี่เหนือประมาณ 3.4 kHz | ข้อมูลในย่านที่ถูกตัดจะไม่เหลือให้โมเดลใช้ |
| **Companding** | แปลงเสียง 16-bit linear เป็น 8-bit logarithmic แบบ A-law หรือ μ-law | ข้อมูลยังอยู่ แต่สัญญาณเปลี่ยนไปจากการ quantize |

งานส่วนใหญ่มักใช้โคเดกครบทั้งกระบวนการแล้วรายงานผลรวมเพียงค่าเดียว การวัดสองส่วนแยกกันจะช่วยบอกว่าการปรับวิธีฝึกโมเดลมีแนวโน้มช่วยได้เพียงใด หรือข้อจำกัดหลักมาจากแบนด์วิดท์ที่หายไป

## คำถามวิจัย

1. **การแยกผล:** จาก EER ที่เพิ่มขึ้นภายใต้ G.711 จำลองบนเสียงภาษาไทย มีส่วนที่สัมพันธ์กับการลดแบนด์วิดท์เท่าใด และสัมพันธ์กับ companding เท่าใด
2. **ความสัมพันธ์ระหว่างระดับกับผล:** เมื่อค่อย ๆ ลดความถี่ตัด ประสิทธิภาพการตรวจจับเปลี่ยนไปอย่างไร และข้ามเกณฑ์ล้มเหลวที่กำหนดไว้ที่ความถี่ใด
3. **การบรรเทาผลกระทบ:** การฝึกด้วยเสียงที่จำกัดแบนด์วิดท์ช่วยกู้ประสิทธิภาพกลับมาได้หรือไม่ และได้มากเพียงใด

## สมมติฐาน

- **H1 — สาเหตุ:** การลดแบนด์วิดท์ส่งผลมากกว่า companding
- **H2 — ปริมาณ-ผล:** EER เพิ่มขึ้นแบบทางเดียวเมื่อความถี่ตัดลดลง และมีจุดพังที่ระบุได้
- **H3 — การบรรเทา:** การเพิ่มข้อมูลแบบจำกัดแบนด์วิดท์ลด `ΔEER` เทียบกับ baseline สถาปัตยกรรมเดียวกันที่ฝึกด้วยเสียงสะอาด

การออกแบบนี้สมมาตร ไม่ได้สร้างขึ้นเพื่อยืนยัน H1 ทุกสมมติฐานให้ผลที่รายงานได้ไม่ว่าจะออกมาทางใด และเกณฑ์ทั้งหมดถูกกำหนดตายตัวก่อนการให้คะแนน จึงเลื่อนเป้าหมายหลังเห็นผลไม่ได้ หาก companding ส่งผลมากกว่าที่คาด การฝึกให้โมเดลทนต่อช่องสัญญาณอาจช่วยได้มากขึ้น หากการเพิ่มข้อมูลช่วยได้น้อยหรือไม่ช่วยเลย ผลจะสอดคล้องกับการสูญเสียข้อมูลจากการลดแบนด์วิดท์ แต่ยังต้องพิจารณาคำอธิบายอื่นร่วมด้วย

## การออกแบบ

![รูปแบบการทดลอง BandGap-TH](docs/architecture.svg)

ไฟล์ต้นฉบับที่แก้ไขได้: [`docs/architecture.mmd`](docs/architecture.mmd)

**ชุดแยกสาเหตุ** — เสียงทดสอบแต่ละไฟล์สร้างครบทั้งสี่เงื่อนไข จับคู่กัน:

| ID | เงื่อนไข | ประกอบด้วย |
| --- | --- | --- |
| C0 | 16 kHz linear PCM สะอาด | อ้างอิง |
| C1 | 8 kHz **linear PCM** ไป-กลับ | แบนด์วิดท์อย่างเดียว |
| C2 | G.711 μ-law | แบนด์วิดท์ + companding |
| C3 | G.711 A-law | แบนด์วิดท์ + companding |

**C1 คือส่วนที่เป็นการมีส่วนร่วมเชิงระเบียบวิธีของโครงงานนี้** งานที่ตีพิมพ์ก่อนหน้ามักใช้โคเดกครบทั้งกระบวนการแล้วรายงานค่าการเสื่อมรวมเพียงค่าเดียว ส่วน C1 ตัดย่านความถี่สูงออกแต่ยังคงความละเอียดแบบ 16-bit linear จึงเกิดการลดแบนด์วิดท์โดยไม่มี companding การเปรียบเทียบ C1 กับ C0 แยกผลของแบนด์วิดท์ออกมา และการเปรียบเทียบ C1 กับ C2 และ C3 ใช้ประมาณการเปลี่ยนแปลงเพิ่มเติมที่สัมพันธ์กับ companding หลังจากลดแบนด์วิดท์แล้ว หากไม่มีเงื่อนไขควบคุมนี้ ทั้งสองสาเหตุจะแยกออกจากกันไม่ได้

**ชุดกวาดความถี่:** เริ่มจากเสียงอ้างอิง 16 kHz ที่ไม่เพิ่ม low-pass filter แล้วตามด้วยความถี่ตัด 6000, 4000, 3400, 2500, 1500 และ 800 Hz

ชุดกวาดความถี่คงอัตราสุ่มไว้ที่ 16 kHz และเปลี่ยนเฉพาะความถี่ตัดของฟิลเตอร์ เพื่อไม่ให้การ resample กลายเป็นตัวแปรเพิ่ม ชุดแยกผลยังต้องแปลงผ่าน 8 kHz เพื่อแทน G.711 แต่ชุดกวาดความถี่ไม่จำเป็นต้องทำเช่นนั้น

## ผลลัพธ์หลัก

```text
ส่วนของแบนด์วิดท์  = EER_C1 − EER_C0
ส่วนของ companding = mean(EER_C2, EER_C3) − EER_C1
ช่องว่างการระบุสาเหตุ = ส่วนของแบนด์วิดท์ − ส่วนของ companding

Recovery = (ΔEER_baseline − ΔEER_augmented) / ΔEER_baseline
```

การเปรียบเทียบแต่ละคู่ใช้ paired cluster bootstrap ตามไฟล์เสียงต้นทาง โดยเงื่อนไขทั้งหมดที่สร้างจากไฟล์เดียวกันจะถูกสุ่มไปด้วยกันในแต่ละรอบ

พร้อมกับกราฟความถี่ตัด และจุดพังที่กำหนดไว้ล่วงหน้าสองแบบ คือจุดที่ EER เพิ่มเป็นสองเท่า และจุดที่ EER ถึง 10%

## ทำไมคำตอบจึงสำคัญ

วิธีรับมือการเสื่อมจากช่องสัญญาณที่ใช้กันทั่วไปคือการฝึกโมเดลด้วยเสียงที่ผ่านช่องสัญญาณ (channel-aware augmentation) เพื่อให้โมเดลเรียนรู้ที่จะทนต่อมัน วิธีนี้จะมีโอกาสได้ผลก็ต่อเมื่อความเสียหายมาจาก companding เพราะ companding เปลี่ยนแปลงข้อมูลที่ยังคงอยู่ในสัญญาณ แต่หากความเสียหายส่วนใหญ่มาจากการลดแบนด์วิดท์ ข้อมูลนั้นถูกตัดทิ้งไปแล้วและการฝึกโมเดลไม่สามารถเรียกกลับคืนมาได้

| หากความเสียหายส่วนใหญ่มาจาก… | จุดที่การแก้ไขต้องเกิดขึ้น |
| --- | --- |
| **Companding** | ที่ตัวโมเดล การฝึกให้ทนช่องสัญญาณและการใช้ representation ที่ทนทานกว่ายังมีโอกาสช่วยได้ |
| **แบนด์วิดท์** | ที่ช่องสัญญาณ ต้องใช้เส้นทาง wideband เช่น VoLTE หรือ VoIP ที่ใช้ Opus เพราะย่านความถี่ที่ถูกตัดไปแล้วฝึกกลับคืนมาไม่ได้ |

ความแตกต่างนี้เกี่ยวข้องกับการตัดสินใจว่าความพยายามด้านการป้องกันการฉ้อโกงควรลงทุนกับระบบตรวจจับที่ดีขึ้นหรือกับเส้นทางการโทรแบบ wideband และเรายังไม่พบงานตีพิมพ์ใดที่รายงานการแยกผลนี้โดยตรง กราฟความถี่ตัดจะระบุค่าความถี่ให้กับคำถามนี้

## การสาธิต

การกวาดค่าความถี่ตัดทำหน้าที่เป็นการสาธิตไปในตัว และเป็นส่วนหนึ่งของงานหลักที่ผูกมัดไว้ ไม่ใช่ส่วนขยายที่เลือกทำ โดยเล่นเสียงพูดภาษาไทยประโยคเดียวกันที่ทุกความถี่ตัดในชุดการกวาด ตั้งแต่ค่าอ้างอิง 16 kHz แล้วไล่ลงมาที่ 6 kHz, 4 kHz, 3.4 kHz, 2.5 kHz, 1.5 kHz และ 800 Hz พร้อมแสดงคะแนนของระบบตรวจจับเทียบกับกราฟที่วัดได้ และทำเครื่องหมายขอบย่านความถี่โทรศัพท์ที่ 3.4 kHz พร้อมเกณฑ์จุดพังไว้บนแกนความถี่ การสาธิตนี้รันบนแล็ปท็อปจากไฟล์ผลทำนายของ Tier 1 โดยไม่ต้องใช้ GPU ไม่ต้องใช้ toolchain สำหรับ deploy และไม่ขึ้นกับ tier ที่เลือกทำ

กฎการนำเสนออยู่ใน [`docs/feasibility.md`](docs/feasibility.md) คือแสดงคะแนนพร้อมเกณฑ์การตัดสินที่ถูกตรึงไว้และอัตราความผิดพลาดที่วัดได้ ไม่แสดงผลเป็นคำตอบ จริง/ปลอม เพียงอย่างเดียว และใช้เฉพาะเสียงที่โครงงานเป็นเจ้าของหรือได้รับอนุญาตตามสัญญาการใช้ชุดข้อมูล

## ขอบเขตที่กำหนดไว้ล่วงหน้า

ขอบเขตเหล่านี้กำหนดไว้ล่วงหน้าและตรึงไว้พร้อมกับโพรโทคอล ข้อกล่าวอ้างจึงขยายออกไปหลังเห็นผลการทดลองไม่ได้

- ไม่กล่าวอ้างว่าศึกษา **โทรศัพท์จริง** สายจริงยังมี packet loss, jitter, การแปลงโคเดก ลักษณะไมโครโฟนของเครื่อง เสียงสะท้อนในห้อง และการปรับเกน ซึ่งไม่ได้ศึกษาที่นี่ งานนี้คือ G.711 จำลองแบบออฟไลน์
- ไม่กล่าวอ้างว่าเป็นการประเมินโทรศัพท์ภาษาไทยรายแรก ซึ่งเป็นของ [4, 12]
- ไม่กล่าวอ้างข้อโต้แย้งเรื่อง threshold transfer ซึ่งเป็นของ [19]
- ไม่กล่าวอ้างว่าเสนอ architecture ใหม่ หรือทำสถิติสูงสุดใหม่
- ไม่กล่าวอ้างว่าสามารถรองรับโมเดลสร้างเสียงที่ไม่เคยพบ
- ไม่ใช้คะแนนจากโมเดลเพียงค่าเดียวเป็นหลักฐานยืนยันว่าเสียงจริงหรือปลอม
- ไม่สรุปว่าผลใช้ได้กับผู้พูดภาษาไทยทุกคนหรือ deepfake ในอนาคตทั้งหมด
